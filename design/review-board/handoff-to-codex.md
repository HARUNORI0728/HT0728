## H-01・H-02 の仕様（章データ）

**読むもの**
- `src/chapters/README.md`（章データの書き方。最初に読む）、`ch01.ts`・`ch02.ts`（完成済みの見本）、`dev.ts`（新しい仕組みの使用例）
- `design/plot.md §2` の該当章（あらすじ、場面の一覧と発生条件、戦闘の設計＝勝利条件・マップの構想・敵の構成・仕掛け、出撃人数、曲）
- 脚本の該当章（`design/script-ch6-8.md`、`script-ch9-10.md`）の見出しと発生条件、末尾の「実装担当への注記」。脚本はビルド時に `src/script/scenes.ts` へ変換され、場面IDで参照する
- `design/systems.md §6`（章ごとの敵Lv・敵数・味方の想定Lvの目安）

**作るもの**
1. `chNN.ts` の `null` を `Chapter` に書き換える。地図、自軍の初期位置と出撃枠、加入キャラ、敵（種類・Lv・武器・AI・ボス）、増援、勝利・敗北条件、仕掛け、曲、会話（開幕・戦闘中・終幕・幕間を場面IDに割り当て。戦闘中の会話の条件は脚本の見出しどおり）。第10章には `ending: true`。
2. 地図は、見て楽しく戦術的に意味のあるものに。ユーザーは以前「川と道があるだけでしょぼい」「山を小さくポンポン置いただけに見える」と不満を言い、作り直した経緯がある。舞台に合った地形の主役を置き、守る場所・攻め口・迂回路が生まれる配置にする。使える地形記号を幅広く使い、単調な平地を残さない。大きさは plot.md の指定（20×14〜24×16）。見本は `art-samples/map-ch1.png`、`map-ch2.png`。
3. 難しさ：能力を書き換えない自動プレイで、カジュアルならほぼ勝てること。1章30〜40分（11〜15ターン程度）。ユーザーの推し（シルフィエット、エリス、アリエル）が開幕で倒されやすい配置にしない。

**検証**
- `npm run check` と `npm run build` が通ること。
- `play/index.html` をブラウザで開き、`window.__fast = true` で演出と会話を飛ばせる。書きかけの章は `window.__game.startChapter(n)` で、全員そろった仮の名簿から始められる。
- 地図全体を画像にして目で確認する。全ユニットと増援が進入できるマスにいること、敵が自軍へ到達できることを確かめる。
- 自動プレイで通しクリアし、勝率とターン数を記録する。戦闘中の会話が、条件を満たすと全部発生することを確かめる。コンソールエラーが無いこと。
- 完成した地図全体の画像を `art-samples/map-chN.png` に保存する。

**未実装の仕組みの影響**：宝箱と村の訪問（M13）が無いため、第7章の檻は家屋で代用、第8章は宝箱なし。H-03 を引き受ける場合は、第7・8章に反映してほしい。

## 共同作業の決まり（追加の提案）

- **章のファイルは1章1担当**。`src/data.ts` への追記は行単位にとどめ、編集の直前に最新を取り込む。
- **ビルドで作られるファイル**（`src/script/scenes.ts`、`src/art-manifest.ts`、`src/audio-manifest.ts`、`play/`）は、コードを触った側がビルドして一緒にコミットしてよい。取り込みで衝突したら、どちらかを採ってビルドし直せば直る（手で解決しない）。
- 完了したら BOARD.md に、コミット、確認結果（勝率・ターン数）、残件を書く。Claude 側で地図の画像と通しを確認し、体験版に反映する。
